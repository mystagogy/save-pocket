# SKILL.md

## 이름
- `save-pocket-feature-implementation`

## 목적
- `save-pocket` 프로젝트에서 기능을 안전하게 추가/수정한다.
- 보안 기준과 테스트 기준(서비스 + 통합)을 항상 함께 충족한다.

## 사용 시점 (Trigger)
- 사용자가 기능 구현, 버그 수정, 스키마 변경, API 추가를 요청할 때
- 인증/인가/세션/비밀번호 등 보안 민감 영역 수정이 포함될 때
- DB 연동 로직을 추가하거나 변경할 때

## 입력
- 사용자 요구사항(기능/버그/개선)
- 관련 문서:
- `docs/project-plan.md`
- `docs/db-api-design.md`
- `AGENTS.md`

## 출력
- 변경된 코드 파일
- 서비스 테스트 코드
- 통합 테스트 코드
- 필요 시 문서 업데이트(`docs/*.md`)
- 실행/검증 결과 요약

## 작업 절차
1. 요구사항을 MVP 범위와 대조해 작업 범위를 확정한다.
2. 관련 코드와 문서를 탐색해 영향 범위를 파악한다.
3. DB 변경이 필요하면 최소 스키마부터 반영하고, 명명/인덱스/제약을 확인한다.
4. 서비스 계층 비즈니스 로직을 구현/수정한다.
5. API/DTO/컨트롤러를 반영한다.
6. 서비스 테스트를 작성한다.
7. 통합 테스트를 작성한다.
8. 보안 체크리스트를 점검한다.
9. 문서를 동기화하고 결과를 보고한다.

## 보안 체크리스트 (필수)
- 비밀값(DB 비밀번호, 토큰, API 키)을 코드/문서에 하드코딩하지 않는다.
- 민감값은 `.env`/환경변수로만 주입한다.
- 로그에 비밀번호/토큰/세션ID/개인정보를 남기지 않는다.
- 인증 실패/권한 오류/검증 실패 케이스를 테스트에 포함한다.

## 테스트 기준 (필수)
- 서비스 테스트:
- 비즈니스 규칙
- 상태 전이
- 예외 처리
- 통합 테스트:
- DB 연동
- API 요청/응답
- 인증/인가 흐름
- 신규/수정 기능은 서비스 + 통합 테스트를 모두 추가해야 완료로 본다.

## DB 규칙
- MySQL 기준
- 테이블/컬럼명은 `snake_case`
- 상태/이벤트 enum은 문자열 저장
- 스키마는 작은 단위로 점진 반영

## 금지사항
- 민감정보 커밋
- 기존 기능을 깨뜨릴 수 있는 무검증 대규모 변경
- 테스트 없이 완료 처리

## 완료 조건 (Definition of Done)
- 요구사항 충족
- 서비스 테스트 통과
- 통합 테스트 통과
- 보안 체크리스트 충족
- 문서 동기화 완료
